## 0. 本文件的作用与边界

前一份文档([REQUIREMENTS_DESK_RESEARCH.md](REQUIREMENTS_DESK_RESEARCH.md))的产出是**候选**需求(它自己标的是 "Candidate")。本文件把它规范化为**可执行、可追溯的基线**。

**必须遵守的证据边界:**

> 本基线的需求来自**桌面研究**和**五名成员的内部角色工作坊**,**未经真人访谈或外部可用性测试验证**。因此每条需求都带「状态」列。在外部验证完成前,**不得声称任何标为「假设」的需求已被用户证实**。

**本基线相对研究文档的三处扩充:**

1. 补齐**管理员**角色的需求(研究文档里管理员只出现在角色卡,没有任何 FR)。
2. 补齐 AI 内容生成的**多产物**需求(原 FR-05 只写了「一个课程草稿」)。
3. 为每条需求补上**可测的验收标准**与**对应的设计章节**。

## 2. 范围与优先级(MoSCoW)

> ⚠️ **本节的优先级分配尚未经团队会议确认。** 它是基于 [PROJECT_PLAN.md](PROJECT_PLAN.md) 的原始提议,并按方案文档的实际范围修正而成。

| 优先级 | 范围 |
| --- | --- |
| **Must** | 三角色登录与 RBAC;课程目录 / 播放器 / MCQ / 进度;教师创建-编辑-预览-发布;AI 生成**教案 / 课件 / 考题 / 模拟卷**;材料上传与检索;内容来源标记;对话式修改与确认;导出 pptx / docx / pdf;**管理员三块(用户 / 课程 / 生成审计)**;基础分析 |
| **Should** | 学生 onboarding 与推荐;CSV 学生导入;教学目标覆盖率检查;错题驱动的补救生成;产物版本历史与回滚 |
| **Could** | 术语白话化与无障碍替代文本;**视频(AI 旁白幻灯片)**;徽章;学习者自建学习路径 |
| **Won't(本版)** | 支付、直播课、社交动态 / 论坛、无拘束 AI 导师、复杂推荐算法、文生视频模型 |

**为什么视频从「产物」降到 Could:** 它是方案里成本最高的一项(TTS + 时间轴 + Remotion 渲染),但不对应任何一条评分顶档要求,且可复用课件成果后补。

## 4. 非功能需求

`NFR-01`–`NFR-05` 沿用研究文档,`NFR-06` 起为本基线新增。

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| NFR-01 | 学生与教师主流程在桌面与手机尺寸均可用 | Must | 320px 宽无横向滚动;关键操作可完成 |
| NFR-02 | 角色授权由**后端**强制,不只是前端隐藏 | Must | 越权请求返回 403(见 FR-01) |
| NFR-03 | LLM API key 只存于后端环境变量 | Must | 前端产物与网络响应中不出现任何 key |
| NFR-04 | AI 内容在教师发布前标记为草稿 | Must | `status=draft` 的产物对学生接口不可见 |
| NFR-05 | AI 错误可恢复,并给出重试/编辑选项且不泄露密钥 | Must | 非法输出、超时、上游失败均返回可理解的错误 + 重试入口 |
| NFR-06 | 单点失败不得导致整份产物失败 | Must | 一个资产或一个章节失败后,其余内容仍可预览,失败项标记待重试 |
| NFR-07 | 长耗时生成以异步作业执行并可观测进度 | Must | 生成不阻塞请求;进度可按阶段推送 |
| NFR-08 | 关键界面可键盘操作,图片含替代文本 | Should | 焦点可见;所有 `<img>` 有 `alt` |
| NFR-09 | AI 生成记录与版本可留存、可审计 | Must | 保留发起人、模型标识、时间、diff 与理由 |
| NFR-10 | 每次生成的模型调用量可观测 | Should | 可给出 token 用量与估算成本(不存密钥) |

## 6. 未验证假设清单(答辩时必须如实说明)

| # | 假设 | 若被证伪的影响 |
| --- | --- | --- |
| 1 | 教师愿意用 AI 起草教学材料,并接受「先草稿后审核」的流程 | 整个 FR-05 / FR-09 的前提失效 |

**这 6 条在外部验证前,都不得在报告或幻灯片中写成已证实的用户需求。**
