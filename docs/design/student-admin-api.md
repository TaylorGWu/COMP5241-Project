# Student and administrator portal API

All routes are under `/api`, use the existing opaque session cookie, return `Cache-Control: no-store`, and require a matching Origin and CSRF token for mutations. Errors use FastAPI's `{detail: ...}` shape. Student routes require an enabled student account; administrator routes require an enabled admin. The existing `/admin/applications/*` qualification endpoints are unchanged.

## Student

- `GET /student/home` returns `{courses, profile: {background, goal}, recommendation}`. Recommendation is either null or `{courseId,reason}`: deterministic word matching against the background and goal, excluding already enrolled courses. Each course has `{id,title,description,courseCode,subject,level,durationMin,chapterCount,enrolled,completionPercent,lastChapterId,lastSlideId}`.
- `PUT /student/profile` accepts `{background,goal}`, each at most 500 characters, and returns `{profile}`.
- `GET /student/courses/{id}` returns `{course,chapters,enrolled}`; chapters contain `{id,title,slideCount,questionCount,completionPercent,completed}`. `POST /student/courses/{id}/enroll` returns the same shape and is idempotent.
- `POST /student/join` accepts `{code}` and returns `{courseId}`. Codes are generated by the instructor's existing `/demo/courses/{id}/invites` route. A code works only for its available course.
- `GET /student/courses/{id}/chapters/{chapterId}` returns `{chapter,progress,results}`. Chapter contains `{id,title,slides,questions,glossary}`. Questions contain only `{id,stem,options:[{id,text}]}` before submission. Slides have safe content fields and `visuals` of `{id,kind,altText,url}`; quiz bullets are omitted to avoid leaking answers. Glossary entries contain `{term,plain}`.
- `POST .../progress` accepts `{slideId}` and returns `{progress}`. Progress is `{visitedSlideIds,lastSlideId,completionPercent,completed}`; completion is based on current slide visits and at least one attempt for every supported MCQ. A wrong answer still counts as participation.
- `POST .../attempts` accepts `{questionId,optionId,submissionId}` and returns `{result,progress}`. Result contains `{questionId,selectedOptionId,correct,correctOptionId,explanation,attemptId}`. Submission IDs are unique per student and retrying the same payload is idempotent; reusing one for a different answer or changed question returns 409. Results are keyed by question ID on chapter reads, and are hidden when the published question changes.
- `GET .../assets/{assetId}.{svg|png}` serves only a ready asset referenced by a slide in the current snapshot, to enrolled students. Diagram SVG/PNG is rendered deterministically; illustrations are private PNGs. No file path or prompt is returned.

Only published, unsuspended courses are available. A teacher's later edits do not affect the snapshot until another explicit publish. Withdrawals and suspensions retain learning records. Progress ignores removed IDs. Supported MCQs have valid options and an answer matching an option; other question types are not graded.

## Administrator

- `GET /admin/overview` returns counts `{users,courses,publishedCourses,pendingApplications,enrollments}`.
- `GET /admin/users` returns `{users:[{id,name,email,role,status,active,createdAt}]}`. `PATCH /admin/users/{id}` accepts `{role?,active?}` and returns `{user}`; it prevents self-lockout and disabling or demoting the last enabled administrator, and revokes the affected account's sessions. Assigning instructor starts qualification review pending.
- `GET /admin/courses` returns `{courses:[{id,title,courseCode,ownerName,status,archived,moderationReason,chapterCount}]}`. `POST /admin/courses/{id}/archive` accepts a nonempty `{reason}`; `POST .../restore` returns the course without changing its publication status or content.
- `GET /admin/audit` returns `{events:[{id,kind,actor,title,status,at,courseId?,reason?,model?}]}`. Qualification decisions, portal administrative actions and safe existing generation/version/patch summaries are included. Existing records without time, model or actor have null values; raw patch payloads and generation inputs are never returned.

Portal schema version 3 seeds snapshots once for already-published legacy courses and backs up a populated database before upgrade. The explicit HTTP publish transaction updates course status and snapshot together under the same SQLite write lock used by moderation. The existing teacher version history is recorded after that transaction and therefore is not atomic with publication. Disabling an instructor revokes their sessions but leaves their published courses available until an administrator suspends them or an authorized instructor withdraws them.
