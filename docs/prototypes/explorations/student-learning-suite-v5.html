Requirements elicitation / Better questions

Ask about the work before you ask for features.

Good requirements start with the problem someone faces, the way they handle it today, and what would make the situation different.

Start with a process, not a solution

“We need an approval system” is a proposed solution. Before deciding what to build, find out how approval currently happens, where it breaks, and who makes the final decision.

Too narrow

“Do you need an approval system?”

Better starting point

“How do you currently approve this? Where does it get stuck?”

A useful question reveals a workflow, an exception, or a decision rule. A yes-or-no question usually only confirms an assumption you already had.
